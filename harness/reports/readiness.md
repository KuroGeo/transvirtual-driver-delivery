# Harness 实际能力审计

本次目标是让技能团队能自主推进工程，遇到问题能发现、返工、复验；以真实协作结果验收。本地能力与生产资格分别记录，[状态](status.json) 是当前审计结果，生产判定仍需执行 [gate.py](../gate.py)。这些项目门槛不是外部认证。

## 设计取舍

参考 [OpenAI Harness engineering](https://openai.com/index/harness-engineering/) 的短入口、仓库事实、可读工具反馈、机械依赖约束和 Agent 互审；按这个 Flutter 客户端的风险落地。CLI + JSON + OS flock 足以支撑当前工作，没有另造调度平台或遥测服务。具体业务事件来自实际事务/同步，资源租用保护命令运行，协作 runtime 负责模型 Agent 生命周期。

工程职能收敛为九个岗位，开发和测试也有仓库内 skill。共同规则只放团队协议；业务需求在 mission、接口在 contracts，命令实现只有一份。任务图和审计状态使用 JSON，运行工具只依赖 Python 标准库。一次失败形成具体修复与行为回归，避免把每个观察都扩成通用框架。

## 生产 no-go 的具体原因

完整地图工作台的本地功能已在历史 `381730` 候选接受；最新箭头、横屏和门禁修复的当前验证见状态；[任务图](../project/backlog.json) 中 E09/#31、X05/#32、E12/#33 继续分别跟踪真机性能、实际强制路径和生产交付。模拟器与受控 HTTP fixture 的结果不能代签真实后端、真机 profile/release、生产资源许可或签名发布。

私有 GitHub 仓库保护设置 API 实际返回 403。历史源码 HEAD `0693165` 的 Linux CI 38102904327 已真实通过并独立核验，但 required checks 和发布强制路径仍未部署。当前生产 gate 的实际首个短路检查因 `enforcement_deployed=false` 返回 exit1；不宣称这一次逐项执行了后续生产检查。未修改仓库隐私、套餐或保护设置。生产还缺约定真机预算、真实服务、适用资源许可、签名、具体发布授权与交付回执。

[正式门禁回归](../tests/test_gate.py) 保留：缺失/失败/跳过/旧候选/hash错配/网页冒充原生/debug冒充真机/fake冒充connected/未签产物/授权与交付错配均拒绝。不能用主控评分、合成正向 fixture 或改交付名字覆盖实际缺口。
