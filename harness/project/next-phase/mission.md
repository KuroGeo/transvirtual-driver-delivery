# 下一阶段需求与范围

2026-10-12 用户已确认原型并授权方案、Harness 任务包与父子 issue 发布。产品执行仍未授权。本包为 prepare；旧 Flutter parity 合同保持原版本。

默认采用推荐 A 地图首页、企业已有身份登录、外部导航与人工确认 AI 提案；具体供应商/公司配置未冻结。

| ID | 用户行为/不变量 |
| --- | --- |
| NP-R01 | 企业已有身份登录：选择受信公司后使用已有身份系统登录；取消、重复/迟到回调与失败可恢复。 |
| NP-R02 | 账号数据归属：同 email 不同 issuer、公司/司机切换、legacy 数据均隔离；退出不删除待同步。 |
| NP-R03 | 账号同步可靠性：旧 scope 在途 ACK 不污染新账号；仅匹配持久确认清队列，重试原 operationId。 |
| NP-R04 | 道路路线与 ETA：从可信起点计算到站点道路路线，标注来源/时间；权限/定位/服务失败可恢复。 |
| NP-R05 | 外部导航交接：司机选择地图应用，失败有降级；交接状态与真正导航/到站分开。 |
| NP-R06 | 来源返回与手动到站：导航返回原站点和入口；到站、AI 提醒不自动改变配送终态。 |
| NP-R07 | 独立计划一致性：计划站序/下一站/列表同版，事务应用与条件撤销；调序不改变配送 outbox。 |
| NP-R08 | 智能派送规划：基于道路矩阵、完整 pending 集、时窗/停留/约束求可行站序，先预览后应用。 |
| NP-R09 | 时效与下一站提醒：确定性时钟/时区规则驱动提醒、去重、暂缓和设置；终态/换账号清对应提醒。 |
| NP-R10 | 有来源的助手回答：下一站/风险查询附数据来源、时间和新鲜度；未同步本地终态覆盖旧快照。 |
| NP-R11 | 人工提案与版本保护：模型只查询/提案；Apply/Undo 检查 scope、revision、fingerprint、expiry 与站点集合。 |
| NP-R12 | 离线与故障恢复：失效登录、算路/AI 失败、进程重开不丢结果；没有真实来源不编造 ETA。 |
| NP-R13 | 服务权限与预算：服务端鉴权、工具白名单/schema/配额/取消/脱敏；secret 不进入 App。 |
| NP-R14 | Harness 机械边界：新需求/场景纳入指纹、受控 fixture、观察与候选绑定门禁，反例失败闭合。 |
| NP-R15 | 独立原生与真实服务验收：网页/fixture/模拟器/真机/真实 SSO 与服务分别签字，不能互相代签。 |
| NP-R16 | 增量性能与生产门槛：真实 30 站工作负载与成本/耗时/电量预算有证据，交接 #31/#32/#33；生产 no-go。 |

不自动扩展自助注册/管理员门户、持续后台定位、语音识别、AI 自动完成配送、地图离线包或生产发布。外部资源具体阻塞项见 NP00/NP13/NP14。
