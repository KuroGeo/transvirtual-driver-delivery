## Frozen behavior

- Default road adapter is explicitly UnavailableThirdPartyRoutePort: no credentials/configured licensed road service exists. No fixture/straight line/fixed Sydney reference may produce a production route/ETA. Do not add an unlicensed public routing endpoint. This blocks NP13 real-road verification only; base Maps handoff is fully implemented. RouteRepository validates provider/configRevision, computedAt/expiresAt, origin freshness/accuracy, departure/arrival/duration basis and geometry. No persistent route cache until provider cache terms are verified. Timeout 8 seconds; explicit retry, no automatic loop.
- Location is requested only after explicit 'Use my location'. Device fix maximum age 2 minutes, accuracy <=100 metres, future timestamp tolerance 5 seconds; permission denied/service disabled/timeout/stale degrades to Maps choosing origin. A driver may explicitly select/confirm a starting coordinate. No fixed reference used as location.
- Pure third-party port input contains coordinate origin/destination, departure and driving mode only. Local scope/stop/request IDs never leave this boundary; no own token, identity, note, operationId or custom proxy URL. External URI allowlist: Apple maps / Google maps driving directions, necessary coordinates only. Google universal URL is explicit browser alternative; native Apple/iOS and Google/iOS/Android app schemes have truthful unavailable/launchFailed statuses. No arbitrary URLs.
- Navigation UI retains the underlying DeliveryViewModel, detail origin/list session/query and map controller/viewport; it does not reload/recreate/record delivery on handoff or return. Handoff requested is not navigation started or arrived. Lifecycle resume can mark returned only after a successful handoff and an observed inactive/paused transition. Async callbacks bind scope/generation/dataset/stop/input revision; switch/invalid stop prevents old UI/result/launch. Completed deliveries remain manual and outbox bytes unchanged.
- UI: detail Navigate → route preview (destination, honest source/failure, optional current or confirmed start, route map only for valid licensed result) → navigator selection → handoff status/return to delivery. Failure offers another app, browser map, copy address. Return to delivery goes to original detail, then its existing source back behavior. Large text scrolls safely.

## Public interface freeze

`RouteCoordinate(latitude,longitude)`, `NavigationScope(workspaceId,principalId,sessionGeneration,datasetId)`, `NavigationTarget(stopId,coordinate,label,address)`, `RouteOrigin(coordinate,observedAt,accuracyMeters,source)` and `RouteRequest(scope,target,inputRevision,requestId,origin,departureAt)` live in pure `models/route.dart`. `RouteResult` carries provider/config revision/freshness/departure/arrival/distance/duration/geometry/durationBasis/licenseAllowsMapOverlay. `ThirdPartyRoutePort` exposes isConfigured/provider/configRevision and compute with narrow ThirdPartyRouteRequest only. `RouteRepository.preview` returns RouteOutcome. `LocationGateway.currentLocation` returns LocationResult. `NavigationGateway.launch(app,destination,origin,isCurrent)` checks freshness immediately before OS dispatch after every await. `NavigationViewModel` exposes origin/locationStatus/routeStatus/route/routeFailure/handoffStatus/isBusy/isValid and requestPreview/useMyLocation/confirmManualStart/useMapsStart/launch/markBackgrounded/resume/invalidate. Expired results clear from visible state; no cached ETA remains realtime.

Apple choice uses compatible maps scheme; Google iOS uses comgooglemaps scheme, Android google.navigation for Maps-chosen origin and native-only universal directions for supplied origin. Browser alternative uses a supported in-app browser view, preventing silent native fallback. All launch results remain request acknowledgements, not route or arrival confirmations. Geolocator 14.1.1 is pinned; foreground-only, one-shot location, no background tracking.
