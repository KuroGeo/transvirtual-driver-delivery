## 验收条件

- [ ] 冷启为地图主屏，搜索筛选/最近站点/列表/详情完成同一业务链；本地失败有恢复入口，瓦片网络不阻塞首屏。
- [ ] 左侧按钮直接同步，不新增 Sync centre/队列抽屉；空队列、进度、离线中断、发送/确认失败、完成分别表达真实结果。
- [ ] Toast 在地图/列表/详情均实际可见，避开概览/工具栏/键盘，不抢焦点、不关闭卡片、不改变镜头；减少动效仍能读到状态。
- [ ] 配送状态/等待确认/服务配置/online/底图独立；局部 Listenable 进度不触发全图排序/重建；终态留详情并按来源返回。
- [ ] 默认 local-client 队列不伪清空，显式 demo 重连按 E05 排空并标模拟；页面返回不创建第二协调器，在途关闭不通知已销毁界面。
- [ ] 独立 E04 测试职能在本条精确集成候选重跑关键用户链和新增 Toast/导航/配置故障回归；组件测试旧通过不能替代本次集成复验。
- [ ] 完整候选 quality 和正式入口 build 通过；产品诊断/安全故障入口能交给 X02，缺失则返工，不用 probe 代签。

## Harness 执行与关闭证据

最低验证层级：G1 集成质量 + simulator debug 构建；G2 交 E08。

在仓库根目录执行（含 `cd app` 的命令除外）：

```sh
python3 harness/run.py quality
python3 harness/run.py build
```

尖括号路径须替换为本任务实际运行目录；计划新建测试/产品入口在实现后运行，不声称当前已有。现有 `test --target` 只支持 `app/test`；`native` 目前仅可靠性 probe；完整 UI/trace 命令由 X00/X02 提供后回填。

关闭时交回：完整产品正式入口与配置运行说明；同候选质量/构建/集成测试日志与受控观察入口。原始记录放 `harness/runs/<实际任务运行>/`，报告关联精确候选、配置、设备/数据来源、命令/退出码/日志 hash 与每个需求判定。

开发完成进入 review；独立测试/原生/性能职能分别签对应层级，主控核验后 accepted 并更新 `harness/project/work.json`。缺失/失败/未运行/旧候选不得写 passed；准备材料和网页证据不能证明 Flutter 功能通过。

默认后台操作，遵守 AGENTS 的桌面共存规则。若步骤需前台访问，说明具体需要并等待该步骤授权；后台失败不授权抢占前台。
