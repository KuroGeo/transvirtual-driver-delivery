## Harness 执行与关闭证据

最低验证层级：G1 独立风险回归；G2 只交 fixture 不自签。

在仓库根目录执行（含 `cd app` 的命令除外）：

```sh
python3 harness/run.py test --target test/data --target test/sync --target test/widget_test.dart
python3 harness/run.py quality
```

尖括号路径须替换为本任务实际运行目录；计划新建测试/产品入口在实现后运行，不声称当前已有。现有 `test --target` 只支持 `app/test`；`native` 目前仅可靠性 probe；完整 UI/trace 命令由 X00/X02 提供后回填。

关闭时交回：需求→测试/安全故障配置矩阵；同候选原始日志和修复/复验记录。原始记录放 `harness/runs/<实际任务运行>/`，报告关联精确候选、配置、设备/数据来源、命令/退出码/日志 hash 与每个需求判定。

开发完成进入 review；独立测试/原生/性能职能分别签对应层级，主控核验后 accepted 并更新 `harness/project/work.json`。缺失/失败/未运行/旧候选不得写 passed；准备材料和网页证据不能证明 Flutter 功能通过。

默认后台操作，遵守 AGENTS 的桌面共存规则。若步骤需前台访问，说明具体需要并等待该步骤授权；后台失败不授权抢占前台。
