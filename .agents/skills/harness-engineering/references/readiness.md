# Harness 能力与可验证门槛

| ID | 能力 | 必需执行证据 |
| --- | --- | --- |
| H01 | 仓库事实可发现 | 新 Agent 从短入口找到当前合同；来源冲突可判定；链接/需求覆盖/过期文档检查实际执行 |
| H02 | 可复现和隔离环境 | 干净工作树按已锁 SDK/依赖启动原生候选；测试数据/服务/端口和设备责任独立；清理保留业务数据 |
| H03 | 工具与产品可观察 | Agent 可实际运行检查、驱动支持 UI/进程并读取结构化业务错误/日志/trace；失败有具体修复入口 |
| H04 | 边界机械强制 | 模型/UI/Repository 依赖规则、终态、事务与确认身份有实际检查；故意违反样例被拒绝，不能只靠 code review |
| H05 | 风险与故障闭环 | unit/widget/native 各覆盖应负责风险；受控写失败、错 ack、超时和真实进程恢复可复现；缺陷修复有前后证据 |
| H06 | 候选与门禁强制 | 源码/diff、SDK/lock/配置/产物/hash/证据属于同一候选；CI/发布门禁实际拒绝缺证、失败、旧证和跨层冒充 |
| H07 | 中断恢复和资源纪律 | 真正中断/取消并恢复任务；核对活 Agent、diff/产物、任务状态/租用；不重复派工或并发占同文件/设备 |
| H08 | 评测与漂移反馈 | 保存失败反例和未参与修改的评测；skill/模型/工具/合同变化触发回归；测成本/flake/复审并更新最小规则 |

每项记录 status、candidate、evidence、owner、next_check。partial 表示有实际子能力或只有准备材料，不能叫 demonstrated。生产 required=true 的项不能用无解释的 not_applicable 豁免。

门禁至少验证 missing/unknown/skipped/failed/stale/mismatched 的反例均拒绝。不要只验证合法样本能通过；CI job 成功也不等于 repository required check 或发布流程已接入。查不到服务端保护设置/实际发布接线就记录未验证。

Flutter 最小实现保持项目轻量架构：边界检查按依赖语义检测，不按字符串猜全部架构。隔离业务测试数据；真进程恢复使用同安装数据。debug/模拟器可定位问题，真机 profile/release 才支撑硬件性能。日志只存必要业务事件与测试身份，故障注入不进入正式业务配置。

运行面从既有 CLI、设备工具和可读日志起步；不要求为小客户端先搭一套遥测平台。自动化 UI 尚不可用时把相关能力记 blocked，人工记录只是实际执行证据，不能称为 Agent 自主驱动已验证。

长期运行与恢复必须实际试验。文档写“支持 resume”或检查已有任务板，不能替代取消后恢复。先找仍活的负责人、未提交 diff 和资源占用；无法证明租用已释放时不派新的冲突写入者。
