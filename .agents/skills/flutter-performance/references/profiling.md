# Flutter 性能测量协议

## 复现条件

固定设备、刷新率、OS、SDK/依赖、数据集、视口、缓存/网络和操作顺序。记录温度/省电/后台负载等已知影响。不能把不同设备/缓存/数据量的两次数字当优化收益。

正式帧预算采样关闭增强 build/layout/paint 跟踪及与生产无关的诊断负载；定位热点可以单独开跟踪，报告区分两类采样。trace 原文件与指标摘要一起保存。

| 领域 | 场景 | 记录 |
| --- | --- | --- |
| 冷启动 | 进程结束后重开；业务库已有/首导入；瓦片命中/缺失 | 从一致起点到第一可操作业务界面的时间，地图可用时间另记 |
| 流畅性 | 拖缩、密集聚合、列表滚动、搜索、保存/同步 Toast | 采样窗口、UI/raster 时间与超刷新预算帧数；两者不简单相加 |
| 内存 | 多轮地图/列表/详情/失败表单来回，再回到稳定空闲 | Dart heap、external、RSS 按工具可得性分开；对象/控制器留存和趋势 |
| I/O | 导入、结果/outbox 短事务、确认、冷启读取 | 耗时、队列规模、失败/恢复；网络不放事务内 |
| 后台/持续负载 | 仅在支持范围包含时 | 空闲 ticker、任务是否停止；实际电池/温度测量不能用 CPU 数值冒充 |

帧预算由实际刷新率计算：60 Hz 约 16.7 ms，120 Hz 约 8.3 ms；UI 与 raster 分开观察。不要仅以平均 FPS 判断少量严重卡顿。

最低可用基线：各关键动作重复采样，足够覆盖首次与稳态差异；启动至少记录多次独立进程启动。具体重复数和统计方法按项目预算固定，少量启动样本可直接报告范围。30 条业务样本用于首版场景；数百/上千条只在明确容量合同或标为探索压测时使用。

检查点：稳定 MapController、局部订阅、派生排序失效条件、ListView.builder、适当聚合、缓存预算、dispose 和暂停任务。它们是诊断线索，不能单靠代码存在就判定性能通过。

官方入口：[DevTools Performance](https://docs.flutter.dev/tools/devtools/performance)、[DevTools Memory](https://docs.flutter.dev/tools/devtools/memory)。具体工具/API 使用前按已装 SDK 核验。
