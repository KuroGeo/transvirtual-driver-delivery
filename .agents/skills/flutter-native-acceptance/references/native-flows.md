# 原生验收方法

为设备/应用取得独占操作窗口，避免其他 Agent 同时构建、安装或杀进程。

## 核心链

1. 记录安装版本、数据集和初始状态。
2. 切到应用内离线模式，提交多个可区分的结果；失败结果含原因和说明。
3. 记录各结果及待发项身份；真正终止应用进程并保留应用数据。设备支持时保留原 PID 和终止/重开记录。
4. 重开，核验结果、原因、operationId、队列和最后已落盘设置。
5. 对真实断网测试另记录网络层条件。应用内开关只控制应用模式，不证明操作系统已断网。
6. 恢复在线：测试配置观察匹配 fake/mock 确认；未接服务配置观察 waiting 且队列仍在；真实接入配置核对服务端持久接受日志。三者不得混称。

## 重点故障

- 终态再次提交、双击、空/纯空格原因、Other 无说明。
- 保存失败不改变业务标记、不追加队列，并保留输入。
- outbox 插入失败回滚站点结果；确认写失败保留原项。
- 响应丢失、超时、重复/错误确认；重试沿用原身份。
- 同步暂停/页面退出/切换面板，避免第二个循环和 disposed 通知。
- 列表进入详情返回原搜索/筛选/滚动；地图进入详情返回地图。
- 首次无底图、缓存失效、清地图缓存后业务结果仍在。
- 键盘、SafeArea、文字放大、系统返回、可访问性与减少动效。
- 存在已发布 schema 时验证旧库升级；不为验收修改而清库。

插件不支持宿主测试的路径在原生目标补证。模拟器可证明功能路径，硬件性能另交 `flutter-performance`。没有真实设备时明确硬件验收 blocked，不以模拟器结果豁免生产门槛。
