# 工具风方向与版式

## 需求依据

已读取两页原始 PDF、`brief.en.txt` 和 `deliveries.csv`。核心验收是「离线 → 更新多个站点 → 重启 → 在线 → 看队列同步」，不是地图展示或路线优化。初始 CSV 没有日期、路线顺序、司机信息、失败原因、联系电话、包裹数量或 ETA；没有把这些内容补成业务事实。

品类：司机使用的高频配送作业工具。首屏任务：找出需要处理的站点、读清地址与配送时间窗、完成一次明确的终态更新。界面保持英文，便于后续英文面试演示；设计交付说明用中文。

同类基线参考：

- [Transvirtual 官方司机应用说明](https://www.transvirtual.com/delivery-management-software/delivery-driver-app/) 和 [FAQ](https://www.transvirtual.com/faqs/)：离线作业与回到在线后同步。
- [Routific 司机站点详情](https://help.routific.com/en/articles/36-how-to-capture-proof-of-delivery)：从单个站点进入订单详情和交付操作。
- [Routific 时间与任务状态](https://help.routific.com/en/articles/19-live-gps-tracking)：时间线和已完成状态提供任务判断依据。
- [Onfleet Driver](https://support.onfleet.com/hc/en-us/categories/360001498192-Driver)：任务视图、交付与下一个任务的工作流。

这些参考用于工作流和质量基线，没有声称还原其视觉，也没有照搬 GPS、照片、签名、条码或导航功能。

## 共同的北极星

像一张经过整理的配送工作清单：地址一眼可读，操作落点明确，离线时仍有确定的保存反馈。

| 刻度 | 决定 | 依据 |
| --- | --- | --- |
| 能量 | 安静，蓝色只用于主动作和当前选择 | 司机要判断地址和结果，不需要持续吸引注意 |
| 完成度 | 精致，22–24px 外边距、统一 1px 分隔与 10–12px 控件圆角 | 靠对齐与公差体现质量 |
| 密度 | 中等，每屏保留完整任务和操作入口 | 避免小字塞入更多信息 |
| 分量 | 标题和客户名称较重，其余清楚降级 | 强调正在处理的对象 |
| 严肃度 | 专业、短句、稳定的位置 | 工作工具要可预测 |

“高级”在这里是可检查的决定：正文 14–18px；编号与时间为等宽数字；白色画布和墨色主文本；普通记录不加阴影；重要操作固定在底部；只给主要按钮轻微实体按压感；状态使用文字与图标双重表达。

## 参考转化为八项决定

| 关系 | 本产品决定 | 原因 |
| --- | --- | --- |
| 任务为首屏主角 | 标题后直接给筛选和站点 | 每次进入都要办事 |
| 当前对象与动作相邻 | A/C 在详情底部，B 在当前任务下方 | 减少跨区域寻找 |
| 地址是实际行动依据 | 地址正文独立成行，不收进详情说明折叠 | 客户名称相同也可区分站点 |
| 编号用于核对 | 完整 TV 编号保留，短序号仅辅助定位 | 不把序号伪装成路线顺序 |
| 时间用于扫描 | 等宽时间、C 按真实 time_window 分组 | 不编造 ETA 或超时判断 |
| 结果必须可观察 | Completed/Failed 与待同步文字分开 | 本地完成与网络确认是两个事实 |
| 主次动作不同分量 | 蓝色完成按钮，失败入口为次操作 | 减少误触失败终态 |
| 反馈保持连续 | 筛选移动滑块，详情从右侧进入，失败表单从底部滑入 | 用户能理解视图来路 |

## 三种版式方向

共同字体、配色和图标固定，只比较布局与操作组织。用户已明确工具风，因此按 Oil UI 规则跳过风格卡阶段。

| 字段 | A 清单优先（推荐） | B 当前站点优先 | C 时间窗优先 |
| --- | --- | --- | --- |
| 生成引擎 | 配送人员手上的清单 | 装卸台上的当前交付对象 | 配送计划中的时间窗分批 |
| 首屏骨架 | 两行标题、进度、筛选、搜索、约 2–3 条站点 | 一张当前任务与直接操作，下面是其他站点 | 时间筛选后立即给第一组站点 |
| 页面结构 | 单列列表 → 单个详情 | 当前任务工作区 + 其他任务列表 | 分组列表 → 单个详情 |
| 主视觉 | 可直接读的名称、地址和参考编号 | 当前客户与地址的尺度对比 | 时间窗作为分组锚点 |
| 结构突破 | 把离线和队列当常驻工具状态，减少大告警横幅 | 完成按钮进入首屏，不需要先打开详情 | 时间窗成为主组织方式，替代平铺列表 |
| 记忆点 | 完成立即终态，待同步徽标接手网络确认 | 完成后明确「选择另一站」，不暗示自动优化路线 | 同一时间窗内做状态筛选，方便查漏 |
| 放弃 | 大地图、指标卡片、营销文案 | 默认把完成后自动切站当作路线建议 | 倒计时、伪造迟到和推算 ETA |

A 推荐理由：30 个站点的客户、地址、编号与状态可持续扫描；搜索和状态筛选满足题目；详情将误触风险较高的终态操作集中管理；Flutter 实现可保持两屏加一个底部表单，适合 4–6 小时题目时间盒。

B 适合严格单站作业，但占用更多首屏空间；C 适合按时间窗批次处理，却需要更多筛选理解。本轮保留三者让用户比较，不混成一个同时有三种组织方式的主界面。

## 视觉变量与状态

- 字体：系统无衬线，标题 27–31px / 650–750，名称 17px / 650，正文 14–18px；`ui-monospace` 用于编号、坐标与时间。
- 色彩：主文本 `#182332`，辅助 `#596675`，主操作 `#2458e0`，表面 `#ffffff` / `#f6f7f9`，完成 `#226348`，待同步 `#895410`，失败 `#a0373e`。
- 图标：Carbon，严格网格和填充轮廓；只在操作或状态有识别价值时使用。
- 控件：按钮 44px 以上点击高度，主按钮 54px；输入 44px；按下即时回应；焦点轮廓可见。
- 设备：390 × 844 默认手机；320–430px 自然重排；桌面仅承载固定 390px 手机画布。

状态覆盖：在线 / 离线、pending / completed / failed、等待发送 / 正在发送 / 已发送、失败原因未填 / Other 空白 / 有效、保存失败及重试、无筛选结果、队列为空。原始 failed 缺少原因单独说明来源，不当作新提交无原因的先例。

## 三处基础动效与一处产品巧思

| 动作 | 表现 | 证据 |
| --- | --- | --- |
| 主操作 | 主按钮按下下沉，立即切换到终态与保存提示，队列数量更新 | `evidence/record-complete/record.mp4` 和开始/中间/结束帧 |
| 状态来路 | 筛选共用滑块 220ms 移动；详情 320ms 从右侧进入、190ms 退出；失败表单 320ms 从底部进入 | `evidence/record-filter/record.mp4`，详情与表单截图 |
| 首次进入 | 顶栏、主标题、筛选和内容沿阅读顺序轻微出场，总时长低于 600ms，只播放一次 | `evidence/record-entry/record.mp4` |
| 产品巧思 | 配送终态即时生效，待同步徽标继续承担传输进度；每条确认后从队列移至 Recently synced | `evidence/record-sync/record.mp4` |

工具 App 不做装饰性的滚动叙事。`prefers-reduced-motion` 下转场直接到位，状态和操作仍完整可用。动效探测记录首次进入 7 个元素、主操作 14 个元素发生变化，页面无需整体滚动。

## 减法与自检

删掉欢迎语、四块指标卡、大地图、路线编号承诺、虚构司机/日期、无关导航和普通记录的阴影边框。来源中没有的照片、签名、电话、包裹数和 ETA 不进入本轮。重复的保存说明压缩为离线状态栏与真正操作后的提示。

保留客户名称、完整地址、参考编号、真实时间窗、配送状态、同步状态和明确的主动作。编号、时间和状态的辅助文字最小 12–13px，仅用于短标识；正文与表单为 14px 以上。筛选文字为 13px。

自检发现并修正：B 其他站点的筛选条件优先级错误，原本可能显示 completed；C 窄时间窗按钮自动换行；对比页默认为桌面导致手机原型缩得过小；对比页编号对比度偏低。现在 B 仅显示 pending，C 时间不换行，对比页默认手机视口，编号文字达到工具检查要求。

39 项验证连续三轮通过，包含真实点击、必填原因、终态逻辑拒绝、离线刷新恢复、发送中断后保留队列、确认后重启不重发、写入失败后保留表单并重试、三种布局与四种宽度。未运行 Flutter 构建或模拟器；浏览器检查不证明移动端进程重启、数据库事务或服务器幂等性。本轮是版式选择阶段，未做独立评审或虚构评分。
