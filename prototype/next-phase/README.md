## 本轮设计问题

司机要在一天的配送中完成三个连续动作：用自己的身份取得当天任务；明确下一站与到站方式；在临近时间窗或调整站序时得到有依据的帮助。

“用自己的系统登录”暂按 **所属公司已有身份系统** 理解。原型采用“选择公司工作区 → 公司账号认证 → 回到当天派单”流程。公司认证页是站内交接占位；没有收集密码或真的连接身份服务。演示司机 Jamie Davis、Harbour Logistics 及店铺名称均为虚构。

## 三个首页方案

| 方案 | 信息与操作重心 | 取舍 |
| --- | --- | --- |
| A 地图提醒，推荐 | 地图保留主场；轻量时间窗提醒；Ask Ocean 入口 | 沿用司机已熟悉的地图工作台，新增能力不增加底部页签 |
| B 下一站卡片 | 当前任务、到达时间和导航占据底部卡片 | 下一步清晰，但常驻任务卡挤占地图与整体进度 |
| C 助手工作台 | 打开对话，先看提醒和建议，再进入路线与地图 | 助手容易发现，但常规配送要多一次返回地图 |

三个方案只比较信息组织；登录、导航和提案确认共享同一套流程。

## 可体验的操作链

1. **企业登录**：输入公司工作区，继续公司认证，使用虚构司机身份进入当天 30 个站点；账号页能看到司机、所属公司与提醒设置。
2. **单站导航**：站点详情增加 Navigate to this stop，进入路线预览，展示行驶距离/时间、预计到达和配送时间窗；选择 Apple Maps 或 Google Maps 后进入模拟交接页；返回或到站都回到正确的站点详情。到站后仍由司机手动记录配送结果。
3. **时间窗提醒**：演示时刻固定为 09:42，Wattle Corner Store 的窗口在 10:00 关闭；提醒说明“为什么现在要处理”，可去看路线、延后提醒或关闭提醒偏好。
4. **问下一站**：助手回答客户、地址、到达时间和来源编号，提供前往该站的操作入口。
5. **智能规划**：助手生成提案，展示当前/建议站序、时间窗风险、到达时间和调序理由；司机点击 Use this stop order 后才应用，首页下一站与列表站序同时更新。可 Undo。站序变化不修改配送状态、不新增待同步结果。
6. **账号与恢复**：登录过期时保存的待同步记录保留，重新登录原账号才恢复模拟同步；退出前提示待同步工作归属，退出后进入登录页。离线、助手不可用和建议过期各有独立状态。

## 模拟与验收边界

- 这是浏览器设计原型。新功能没有接入真实账号、服务器、设备定位、道路算路、路况、导航 App、模型或系统语音。界面的语音开关仅用于评审偏好设置，不播放声音、不申请权限。
- 路线、ETA、风险数量与助手回复是固定场景；地图上的虚线是路线展示占位，不能作为道路通行或真实规划证据。选择导航 App 不会打开外部窗口。
- 数据读取公开的合成 CSV。原型局部重命名 4 个虚构店铺，并调整演示时间窗，使 09:42 的紧迫站点场景一致；24 个待配送站点、3 个完成、3 个失败的基线保持一致。
- 账号、方案、助手和本轮操作均在内存中。刷新恢复干净场景。原有原型的持久存储使用不同入口，本轮不会向其写入。
- 退出/过期场景只演示同一司机的待同步记录恢复；真实账号之间的数据隔离与真实身份协议待后续方案设计明确。
- 提醒、导航、规划、身份接入与 AI 的权限、失败恢复和服务约束都须在方案阶段落为工程验收条件。本轮浏览器检查不代表 Flutter、模拟器、真机或生产交付。

截图与实际点击复核记录位于 `evidence/`。最终 **38 项浏览器交互检查通过**，记录见 `evidence/interaction-review.json`；覆盖登录、导航返回、AI 查询/规划、应用/撤销、提醒设置、离线、助手失败、建议过期、账号过期/退出恢复、完成站点后排除，以及 1320/820/430/390px 的宿主画布。本轮主 Agent 看过实际截图并自检，没有独立视觉评审。

视觉复核修正：新面板不再被上一步 Toast 遮挡；导航时隐藏原详情卡；地图工具保持单列，版权署名保留在可见区域；路线 SVG 不继承图标的 20px 尺寸；等待旧站点镜头过渡完成再展示完整路线。新增路由面板有轻量进入过渡，沿用原型按钮按下与面板切换反馈，并支持减少动态效果。未记录动效视频，不将静态截图当作动效验收。
